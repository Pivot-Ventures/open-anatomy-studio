# Open Anatomy Studio 多学科 3D 教育设计决策

> Product, Content, UX and Visual Direction for a Multidisciplinary 3D Learning Platform

- 状态：产品方向 v2，待实施
- 日期：2026-08-04
- 核心公式：医学解剖 + 多学科 + 教育 + 3D
- 对比原型：`demo/styles-gallery.html`
- 适用范围：产品定位、内容模型、3D 教学方式、信息架构、视觉系统与实施路线

## 1. 核心结论

Open Anatomy Studio 不再只被定义为一个解剖器官浏览器，而应发展为一个 **以医学解剖为首个旗舰学科的多学科 3D 教育平台**。

新的产品方向定义为：

> **Multidisciplinary 3D Learning Studio**
>
> 用可操作的三维场景，把抽象知识变成可观察、可拆解、可验证的学习过程。

四个组成部分承担不同责任：

| 组成部分 | 产品责任 |
| --- | --- |
| 医学解剖 | 首个旗舰学科、内容深度样板、科学准确性基准 |
| 多学科 | 平台的扩展能力，支持生命科学、化学、物理、地球科学与工程等方向 |
| 教育 | 决定课程结构、认知路径、任务反馈、评估和学习进度 |
| 3D | 核心教学媒介，不是装饰、封面视频或单纯模型展示 |

医学解剖仍然是当前版本最重要的内容，但它不再是平台永久的内容边界。

## 2. 品牌与范围边界

### 2.1 当前品牌处理

- 当前仓库名和产品名暂时保留为 **Open Anatomy Studio**。
- 本文档不授权自动修改仓库名、域名、路由或品牌标识。
- 当第二个学科进入正式开发时，应单独完成一次品牌命名决策。
- 在品牌升级前，可以使用副标题表达平台方向：`3D Learning Studio`。

### 2.2 产品不是以下形态

- 不是只供旋转和缩放的 3D 模型图库。
- 不是以炫技动画为目标的 WebGL 展示站。
- 不是传统文档系统外加一个 3D 窗口。
- 不是游戏化积分平台。
- 不是医疗诊断、临床决策或专业资格认证工具。
- 不是一次性覆盖全部学科的“大而全”课程平台。

### 2.3 目标用户

- 需要建立空间理解的学生与自学者。
- 需要用三维内容解释概念的教师与内容创作者。
- 对医学、科学和工程主题感兴趣的普通学习者。
- 需要双语学习材料的中文和英文用户。

## 3. 产品价值主张

传统教材擅长给出结论，但二维图像很难充分表达空间关系、尺度变化、内部结构和动态过程。

本产品应解决四类学习困难：

1. **看不见**：内部结构、微观对象、抽象场和隐藏关系难以直接观察。
2. **想不清**：二维图示无法建立稳定的三维心智模型。
3. **记不住**：知识点脱离操作任务，学习者只能被动阅读。
4. **不会用**：学习结果缺少定位、比较、预测和解释等验证环节。

平台的核心承诺是：

> 每个 3D 场景都必须对应一个明确的学习目标、一次有意义的操作和一种可验证的学习结果。

## 4. 核心学习循环

```text
选择学科
  -> 进入主题
  -> 明确学习目标
  -> 操作 3D 场景
  -> 观察结构或现象
  -> 阅读解释与证据
  -> 完成任务或测验
  -> 获得反馈并记录进度
```

用户不应在没有目标的情况下被丢进复杂的三维场景。每节内容首先说明“要理解什么”，然后提供刚好够用的操作工具。

## 5. 多学科内容架构

### 5.1 内容层级

```text
平台 Platform
├── 学科 Discipline
│   ├── 主题 Topic
│   │   ├── 课程 Lesson
│   │   │   ├── 3D 场景 Scene
│   │   │   ├── 对象与结构 Entity
│   │   │   ├── 学习任务 Activity
│   │   │   ├── 评估 Assessment
│   │   │   └── 来源与许可 Sources
│   │   └── 学习路径 Path
│   └── 学科词汇表 Glossary
└── 用户学习记录 Progress
```

### 5.2 核心内容对象

| 内容对象 | 必需信息 | 示例 |
| --- | --- | --- |
| Discipline | 学科名称、简介、范围、视觉标识 | 医学解剖、化学、物理 |
| Topic | 核心概念、前置知识、课程集合 | 循环系统、分子结构、力学 |
| Lesson | 学习目标、难度、预计时间、任务 | 认识心脏、理解共价键 |
| Scene | 模型、相机、灯光、交互能力、降级方案 | 心脏剖切、分子轨道、受力场 |
| Entity | 名称、标签、空间位置、说明、术语 | 主动脉、原子、力矢量 |
| Activity | 操作指令、成功条件、反馈 | 定位、排序、拆解、比较、预测 |
| Assessment | 题型、答案、解释、掌握目标 | 点击结构、判断变化、概念测验 |
| Source | 内容依据、模型来源、许可证、审核状态 | 教材、开放数据、CC BY 资产 |

所有对象都应支持中文和英文，并将内容来源、模型来源和产品行为分开维护。

## 6. 学科扩展规则

以下内容用于说明平台能力，不代表这些学科已进入正式开发。

| 学科方向 | 适合的 3D 教学内容 | 关键交互 |
| --- | --- | --- |
| 医学解剖 | 器官、骨骼、组织层次、空间关系 | 旋转、隔离、透明、剖切、定位 |
| 生物学 | 细胞结构、遗传过程、生态关系 | 分层、缩放、过程动画、顺序观察 |
| 化学 | 分子、晶体、轨道、反应过程 | 键结构、尺度切换、构型比较、过程控制 |
| 物理 | 力、运动、波、场和光学 | 参数调节、矢量显示、轨迹比较、预测 |
| 地球科学 | 地层、板块、大气、天体尺度 | 分层、时间轴、尺度转换、截面观察 |
| 工程 | 机械组件、结构、装配和故障 | 爆炸图、装配、测量、状态模拟 |

新增学科必须满足三个条件：

1. 三维表达能显著提升理解，而不是只让页面更好看。
2. 可以设计至少一种基于操作的学习任务。
3. 内容和模型具有可核验的来源、许可和审核状态。

## 7. 3D 教学语法

3D 场景应从统一的教学动作中组合，而不是每个学科重新发明交互。

### 7.1 观察 Observe

- 旋转、缩放和平移。
- 标签、热点和术语切换。
- 预设视角与相机复位。
- 尺度和方向提示。

### 7.2 拆解 Decompose

- 隔离、隐藏和透明显示。
- 剖切、分层和爆炸视图。
- 组件层级和结构树。
- 内外关系切换。

### 7.3 比较 Compare

- 两个对象并排比较。
- 正常与异常、之前与之后对比。
- 不同尺度、材料或参数对比。
- 差异高亮与同步相机。

### 7.4 模拟 Simulate

- 播放、暂停和逐步观察过程。
- 调整有限且有教学意义的参数。
- 显示时间、轨迹、向量或状态变化。
- 为每个模拟提供初始状态和一键复位。

### 7.5 验证 Assess

- 在模型上定位指定对象。
- 按正确顺序组装或排列。
- 根据参数预测结果。
- 比较两个场景并解释差异。
- 完成概念题并查看解释。

不是每个课程都需要全部能力。界面只显示当前学习任务需要的工具。

## 8. 信息架构

### 8.1 平台级入口

目标信息架构建议包含：

- **学科**：浏览学科和主题。
- **3D 探索**：自由观察可用场景。
- **课程**：按目标组织的引导式学习。
- **学习进度**：继续学习、复习和掌握状态。
- **来源与许可**：内容依据、模型来源和使用边界。

现有导航名称和路由在正式实施前保持不变，避免在设计决策阶段造成无意的产品迁移。

### 8.2 3D 学习工作区

| 区域 | 建议占比 | 当前解剖内容 | 多学科扩展后 |
| --- | ---: | --- | --- |
| 左侧导航 | 20% | 系统、器官、收藏 | 学科、主题、场景、收藏 |
| 中央工作区 | 55% | 器官模型和结构热点 | 3D 场景、模拟、比较和操作任务 |
| 右侧学习栏 | 25% | 结构说明、事实、功能 | 学习目标、解释、参数、任务和来源 |

布局原则：

- 中央 3D 工作区始终是最大区域。
- 右侧内容允许独立滚动，不推动场景跳动。
- 左侧层级最多显示当前任务需要的两到三级内容。
- 操作工具按任务逐步出现，避免一次展示所有高级功能。
- 小于 768px 时使用单列：目标、3D 场景、操作、解释、评估。

## 9. 教育设计原则

### 9.1 目标先于模型

每个课程必须先说明学习者完成后能够做什么。模型名称不是学习目标。

错误示例：

> 查看心脏 3D 模型。

正确示例：

> 能够定位四个腔室，并解释左右心室壁厚差异与功能的关系。

### 9.2 操作必须产生认知结果

- 旋转用于理解方位。
- 剖切用于观察内部关系。
- 隔离用于降低认知负荷。
- 动画用于解释时间过程。
- 参数调节用于建立因果关系。

无法说明教学意义的动画和交互应被删除。

### 9.3 反馈解释原因

测验反馈不能只显示正确或错误，还应解释原因，并允许用户返回场景验证。

### 9.4 探索与课程分离

- 自由探索模式允许用户浏览和发现。
- 引导课程模式限制工具并提供明确任务。
- 两种模式共享同一场景和内容对象，避免重复建设。

## 10. 视觉风格结论

五种风格的基础判断仍然成立，但应从多学科平台角度重新解释。

| 排名 | 风格 | 平台用途 | 使用边界 |
| ---: | --- | --- | --- |
| 1 | 05 Soft Docs | 全平台内容结构、课程、来源和学习反馈 | 不原样复制 Emoji、米黄纸感和卡片堆叠 |
| 2 | 02 Swiss Editorial | 学科首页、主题封面、章节标题和关键概念 | 不让超大字体挤压 3D 工作区 |
| 3 | 01 Playful Gamified | 练习反馈、低龄课程和学习状态 | 不使用虚构 XP、宝石和儿童化主导航 |
| 4 | 04 Dev Terminal | 编程、工程或技术主题的局部表达 | 不作为所有学科的全局外壳 |
| 5 | 03 Neubrutalism | 活动页或短期视觉实验 | 不进入长时间学习工作区 |

最终视觉方向：

> **Structured Learning + Editorial Clarity + Focused 3D Workspace**
>
> 结构化学习、编辑式清晰度与高专注三维工作区。

## 11. 视觉系统

### 11.1 色彩

- 平台保留当前青绿色作为品牌强调色。
- 每个课程页面最多使用一个学科强调色。
- 学科颜色只辅助识别，不替代文字、图标和层级。
- 模型颜色优先表达科学语义，不服从营销配色。
- 医学中的动脉红、静脉蓝和组织色不得被界面装饰滥用。
- 明亮模式采用冷白、灰绿和低饱和中性色。
- 深色模式继续承担高专注的 3D 工作区体验。

### 11.2 字体

- 正文与界面继续使用 Geist Sans 和中文系统字体。
- 数据、参数、来源和快捷键使用 Geist Mono。
- 标题通过字号、字重和网格建立层级，不依赖装饰性字体。
- 中文和英文分别测试导航、按钮、术语和多行标题。

### 11.3 图标与图形

- 统一使用项目现有的 Phosphor Icons。
- Emoji 不作为正式功能图标。
- 学科图标表达真实内容类别，不作为彩色装饰贴纸。
- 图表、向量、轨迹和剖面必须带有单位、方向或图例。

### 11.4 形状与容器

- 使用统一的小到中等圆角系统。
- 卡片只用于真实的层级、任务或状态分组。
- 普通知识内容优先使用留白、标题和稀疏分隔线。
- 3D 场景不使用与模型竞争的外发光和复杂渐变。

## 12. 学习状态与游戏化边界

可以使用：

- 已学习、正在学习、需要复习和已掌握状态。
- 测验即时反馈与原因解释。
- 学习路径和可核验的课程完成度。
- 对儿童或入门内容适度增强的正向反馈。

不使用：

- 与学习目标无关的金币、宝石和虚构 XP。
- 夸张连续登录奖励和焦虑型倒计时。
- 用儿童化吉祥物承担全平台导航。
- 不能解释学习价值的徽章和庆祝动画。

## 13. 来源、许可与质量状态

多学科平台必须让每个内容对象具备可审计状态。

建议字段：

| 字段 | 说明 |
| --- | --- |
| Content source | 教育内容依据和版本 |
| Model source | 3D 模型、数据集或生成方式 |
| License | 代码、模型、图片和数据的使用许可 |
| Review status | 草稿、已核对、专家审核或待更新 |
| Audience level | 入门、中级、高级或教师材料 |
| Learning objective | 可观察和可验证的学习结果 |
| Last reviewed | 最近一次内容核对日期 |
| Locale status | 中文、英文及翻译审核状态 |

不同学科的权威来源标准可能不同，不能用医学内容的审核方式简单套用全部学科。

## 14. 技术与内容架构原则

- 3D 渲染器与学科内容数据解耦。
- 通用交互能力以可组合模块实现。
- 学科差异通过内容模式和场景配置表达。
- 模型、教育文案、交互任务和来源信息分别维护。
- 同一场景可以服务自由探索和引导课程。
- 低性能设备必须提供简化模型、静态视图或文字降级方案。
- 所有自动动画尊重 `prefers-reduced-motion`。
- 重要操作支持键盘、触控和清晰焦点状态。

## 15. 实施路线

### P0：重构平台基础定义

- 将内容模型从 `器官` 抽象为可扩展的 `学科 / 主题 / 课程 / 场景 / 对象`。
- 保持当前解剖数据可用，不因抽象重构破坏现有功能。
- 建立通用的学习目标、任务、评估和来源字段。
- 调整文案，使产品表达从器官浏览升级为 3D 学习。

### P1：重构 3D 学习工作区

- 保持中央 3D 区域为最大视觉区域。
- 将模型控制改为按任务显示的通用工具。
- 建立观察、拆解、比较、模拟和验证五类交互能力。
- 完成加载、空状态、错误状态和低性能降级。

### P2：完成医学解剖旗舰体验

- 用心脏和局部皮肤验证不同类型的 3D 教学任务。
- 为器官内容补齐明确学习目标和模型操作任务。
- 建立结构定位、剖切观察和功能解释类评估。
- 继续完善来源、许可、术语和中英文内容。

### P3：验证第二学科

- 选择一个与解剖不同的 3D 教学案例。
- 优先验证参数变化、过程或尺度，而不是再做一个静态模型图库。
- 使用相同内容模型和工作区，不复制一套独立产品代码。
- 根据试点结果再决定正式品牌升级和学科导航。

### P4：教师与内容创作能力

- 课程编排与场景复用。
- 学习目标、任务和评估配置。
- 来源、许可和审核状态管理。
- 可分享的课程链接和学习结果摘要。

## 16. 验收标准

### 平台层

- 不修改核心渲染器即可增加新的学科、主题和课程。
- 产品首页能够解释“为什么需要 3D 学习”，而不仅是展示模型数量。
- 医学解剖仍保持完整可用，不因平台化重构退化。
- 学科、内容来源、模型来源和审核状态能够独立维护。

### 教育层

- 每节课至少有一个可验证的学习目标。
- 每个 3D 场景至少有一次具有教学意义的操作。
- 每个评估都提供解释，并能返回场景验证。
- 探索模式和课程模式使用同一内容对象。

### 体验层

- 首屏中 3D 工作区面积大于任一信息面板。
- 用户能快速找到旋转、缩放、复位和当前任务操作。
- 页面不会一次展示与当前任务无关的全部高级工具。
- 中英文切换不会造成导航换行、按钮溢出或布局跳动。
- 明暗主题、键盘、触控和减少动态模式均可使用。

### 视觉层

- Soft Docs 提供结构，不形成普通笔记工具外观。
- Swiss Editorial 提供层级，不挤压学习内容。
- 学科颜色不破坏科学模型的语义颜色。
- 不使用 Emoji 功能图标、过量胶囊标签或无意义卡片。
- 所有动效都服务于操作反馈、因果解释或状态变化。

## 17. 下一项独立决策

在进入第二学科开发前，需要单独确认：

1. 第二学科选择及其首个 3D 教学案例。
2. 平台正式品牌名是否继续使用 Open Anatomy Studio。
3. 首要用户是学生自学、课堂教学还是教师内容创作。
4. 内容审核责任和各学科来源标准。

这些决策会影响品牌命名、首页信息架构和内容工具优先级，不应在本轮文档重构中被默默假设。

## English summary

Open Anatomy Studio should evolve from an anatomy viewer into a **multidisciplinary 3D learning platform**, with medical anatomy as its first flagship discipline and quality benchmark. Education defines the learning structure, while 3D serves as the primary medium for observation, decomposition, comparison, simulation and assessment. The platform should keep Soft Docs as its structural foundation, borrow the clarity of Swiss Editorial, and retain a focused dark 3D workspace. A second discipline should be added only after the shared content model and reusable teaching interactions are proven.
